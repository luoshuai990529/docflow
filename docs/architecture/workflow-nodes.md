# 七节点 workflow 契约

`WorkflowStage` 是唯一阶段枚举；`WorkflowRunner` 只接受七个阶段按固定顺序组成的节点列表。节点通过 `WorkflowContext` 接收请求、取消检查和前序产物，并以 `NodeResult` 返回状态、受限计数、领域产物或安全错误码。用户文件、Key、完整提示词和模型响应不进入进度事件。

| 顺序 / 节点 | 输入 | 输出 | 负责范围与失败条件 |
| --- | --- | --- | --- |
| 1 · `preflight` 预检 | 操作、模式、上传文件引用或 prepare bundle | 合法输入路径、哈希/元数据、处理器端口、候选输出位置 | 验证格式/魔数、大小与集合边界、文档结构、活动内容、源文件哈希及运行条件。未知、损坏、过限、被篡改或取消时失败；不发起模型调用，也不创建交付文件。 |
| 2 · `extract` 提取 | 预检通过的问卷与资料 | 结构化题目、选项、填写目标、来源片段和覆盖信息 | 解析 PDF/OOXML/文本/图片，必要时调用受限 DOC/XLS 转换或 OCR；只产出可追溯结构。不猜测未知模板；转换或解析失败停止流程。 |
| 3 · `understand` 理解 | 结构化问卷与原始目标/位置 | 识别出的题目、类型、选项、子问题与可定位目标 | 用本地结构规则和 LLM 解释问卷语义、关联原始题目与目标位置；不生成填写答案。结果必须仍映射到原问卷，取消或无效模型结构会停止后续节点。 |
| 4 · `answer` 作答 | 可定位题目、资料证据、作答模式 | 受契约约束的候选答案、引用/假设及覆盖信息 | 资料模式按资料抽取并整合答案；自主模式生成答案和共享假设，可选 Jev 处理选项。外部调用只返回数据；超时、无效结构或不完整响应按既有策略失败或进入待复核。 |
| 5 · `validate` 校验 | 候选答案、领域问题/选项、来源证据、模式 | `Decision` 状态与可写答案集合 | 检查题号、答案类型、选项、数值/单位、来源引用及填写位置；依据不足或位置不可靠的答案转待复核/留空。自主模式不伪称资料已核实；文字压缩最多两次。只有领域规则允许发布的答案才可进入写入计划。 |
| 6 · `write` 写入 | 原始副本、问卷目标、可写 `Decision` | 新候选文件与逐目标写入记录 | 通过 `WritePlan` 写到独立候选文件，不修改来源文件。依据文档格式生成 PDF、DOCX 或 XLSX。通用 workflow 的 handler 会在本节点执行格式回读/版式试验，以支持受限的写入重试；此过程仍从不可变原件重新生成候选。 |
| 7 · `verify` 验证 | 候选路径、写入记录、验证报告/摘要 | 通过门禁的最终产物清单，或扣留后的诊断结果 | 固定模板路径在这里做回读与版式门禁；通用路径在写入 handler 完成格式试验后，这里核对报告、结果路径、文件哈希和发布标记。任何内容、路径或报告不一致都不能进入公开下载清单。 |

## 操作模式

- `run` 按 `preflight → extract → understand → answer → validate → write → verify` 执行。
- `apply` 在 runner 中把 `understand` 和 `answer` 标为 `skipped`；仍需重新预检、重新提取并核对 bundle 与原件哈希，再校验外部答案数据、写入和验证。该路径不构造或调用模型客户端。
- 任一节点返回失败/中断，runner 保留该节点结果，将后续节点标成 `skipped`。不自动重试任务；报告只能描述本次可核实结果。
- 进度事件只含节点 ID、状态、UTC 时间、限定计数（`completed`、`total`、`attempt`、`batch`、`batches`）和白名单错误码。兼容的五阶段状态是只读投影，不改变旧持久化 schema。

## 实现入口

| 代码 | 契约所在 |
| --- | --- |
| `server/src/autofill/workflow/contracts.py` | 阶段、请求/上下文、节点结果、进度及 node protocol |
| `server/src/autofill/workflow/runner.py` | 固定顺序、`apply` 跳过、取消与 fail-stop |
| `server/src/autofill/general.py` | 通用文档 workflow 的七个阶段 handler |
| `server/src/autofill/core.py` | 固定模板 `run` / `prepare` / `apply` handler 与候选发布门禁 |
| `server/src/autofill/domain/write_plan.py`、`publication.py` | 可写目标与发布判定 |

通用路径为了基于真实排版反馈做有限答案压缩，会在 `write` handler 中串联候选写入和格式验证；`verify` 节点仍负责最终产物/报告一致性检查。两个模式的文档写入/验证差异被显式保留，不能把节点名理解为每个格式都有完全相同的内部调用图。
